## 0. 本次统计的范围与口径

| 项 | 内容 |
|---|---|
| 参与方 | **SECOND**（本文方法）、**MUTANT**（对照 baseline） |
| 数据集 | SMAP / MSL / SWaT / WADI |
| 指标 | 计算成本（params / FLOPs / MACs）、推理延时、峰值显存 |
| 阶段 | **仅推理**（不含训练） |
| 设备 | NVIDIA RTX 5880 Ada Generation，独占，全部测量串行完成 |

**三个指标的口径**

| 指标 | 定义 |
|---|---|
| 计算成本 | batch=1 单窗口前向，`eval` 模式，不含 backward；FLOPs = 2 × MACs |
| 推理延时 | 端到端推理路径（`reconstructed_probability`）跑完一个 batch 的墙钟时间 ÷ 窗口数 → ms/窗口；报 mean / p50 / p95 |
| 峰值显存 | 进程内 `torch.cuda.max_memory_allocated()`，从模型加载完成到推理结束 |

**跨库可比性前置条件（已逐条落实）**

1. **数据与评测协议完全一致** —— 逐行 diff 确认：同一份 npy 数据、同一 `preprocess`（MinMaxScaler）、同一 `bf_search(93→100, step 0.01, 700)`、同一 `val=0.35` 切分。**F1 侧无需再建协议。**
2. **batch 采样点逐点相同** —— 两库均为 `[1, 8, 32, 64, 120]`；`summarize_cost.py` 自动校验并打印 `✅ 跨库 batch 采样点逐点一致`。
3. **operational batch 不作为曲线点** —— SECOND 为 60（WADI 24）、MUTANT 为 120，两边不同，故只在 `config` 中如实记录。
4. **各方法超参不强行统一** —— `window_length` / `latent_size` 等按各自推荐配置，逐行披露。

**超参差异（必须与结果同行披露）**

| | SECOND | MUTANT |
|---|---|---|
| `window_length` | 70（SMAP/MSL/WADI）、35（SWaT） | 20（SMAP/MSL/SWaT）、5（WADI） |
| `batch_size`（operational） | 60、24（WADI） | 120 |
| `latent_size` | 256 | 100 / 120 |
| 数值精度 | 全 FP32 | GCN 为 **FP64** |

> `window_length` 在 SECOND 中必须是 35 的倍数（`patch_size=[5,7]` 要求整除，`Model.py:69`），无法与 MUTANT 的 20 对齐。实测 W 的影响 <2%，见 §6.1。

## 5. 关键发现

**① 两个模型都不是算力瓶颈，且瓶颈位置完全不同。**
SECOND 在 batch=1 时有效算力仅 149~744 GFLOPs/s，batch=120 升到 6.2~7.1 TFLOPs/s 仍未触顶——限制因素是 kernel 数量（中间块的"序列维"是通道维 `l=25~127`，`pscan` 只有 5~7 轮小算子，每层约 60~80 个 kernel × 8 层 ≈ 500~600 个 kernel 的 launch 开销）。
MUTANT 有效算力仅 23~59 kFLOPs/s，其 `returnA` 占端到端延时 68.5%，而其中 **98% 是磁盘 I/O**（`np.corrcoef` 只要 0.06 ms，`returnA` 要 3.33 ms；差额在 `construct_graph` 写 `tmp_{pid}.txt`/`tmp2_{pid}.txt` 再 `np.genfromtxt` 读回）。

**② batch 收益相差一个数量级 —— 这是两者最本质的区别。**
SECOND 的并行性可被 batch 摊薄（9.5~41.7×），MUTANT 的不能（1.18~1.40×）。原因是 MUTANT 的瓶颈（逐样本磁盘 I/O）与 batch 无关。

**③ 交叉点在 batch≈8 附近。**
batch=1 时 SECOND 慢 3.98~6.61×；batch≥32 后反超（as_shipped @b=120 快 2.0~4.5×）。

**④ 通道数 C 越大，最优 batch 越小、batch 收益越小。**

| 数据集 | C | batch 收益 | 最优 batch |
|---|---|---|---|
| SMAP | 25 | 41.7× | 120 |
| MSL | 55 | 20.9× | 120 |
| SWaT | 51 | 21.3× | 120 |
| WADI | 127 | 9.5× | **64**（b=120 反而回升 2.1%，显存 +64%） |

**⑤ 算力与参数差距无法回避。** FLOPs 约 4 万倍（39,747~50,366×），参数量 665~1541 倍，权重显存 727~1902 倍。

**⑥ 显存随 batch 线性增长，C 越大斜率越陡。**
SECOND：b=1→120 从 791→1831 MB（SMAP）到 926→5557 MB（WADI）；MUTANT 几乎持平（16.7→18.7 到 17.9→38.2 MB）。跨库显存比在 b=1 时约 47~52×，b=120 时扩大到 **98~151×**。

**⑦ `as_shipped` 与 `core_only` 给出相反结论，必须双侧披露。**

| | b=120 as_shipped | b=120 core_only |
|---|---|---|
| 谁快 | **SECOND** 快 2.0~4.5× | **MUTANT** 快 2.95~11.8× |

只报一侧都会被质疑：只报 as_shipped 是"拿实现差异当卖点"，只报 core_only 是"藏掉部署时真实发生的开销"。

**⑧ FLOPs 与延时严重脱钩，任何单列指标都会误导。**
SECOND 算力是 MUTANT 的 4 万倍，但在 as_shipped @b=120 下延时只有它的 1/2 ~ 1/4。反过来只看延时也会掩盖算力差距。

## 6. 敏感性分析

### 6.1 window_length 的影响

固定 C=25，只改 W（形状分析，CPU 测量）：

| W | params(M) | vs W=70 | FLOPs/win(G) | vs W=70 | 中间块(G) | 中间块占比 |
|---|---|---|---|---|---|---|
| 35 | 192.67 | −0.44% | 5.0820 | −0.87% | 4.9121 | 96.66% |
| 70 | 193.52 | — | 5.1267 | — | 4.9121 | 95.81% |
| 140 | 195.22 | +0.88% | 5.2161 | +1.74% | 4.9121 | 94.17% |

**独立交叉验证**（WADI，真实 ckpt）：W=70 → W=140 时 params +0.76%、FLOPs +1.71%。

**W 翻 4 倍，成本只差约 2%，中间块恒定 4.9121 G。** 原因：中间块作用在通道维 `[B,C,512]`，与 W 无关，而它占 95% 以上算力。

### 6.2 通道数 C 的影响

固定 W=70，只改 C：

| C | 25 | 55 | 51 | 127 |
|---|---|---|---|---|
| GFLOPs/win | 5.13 | 11.30 | 10.47 | 26.60 |
| 相对 C=25 | 1.00× | 2.20× | 2.04× | 5.19× |
| **C 的比值** | 1.00× | **2.20×** | **2.04×** | **5.08×** |

**FLOPs 几乎严格正比于 C**（误差 <3%）。**C 才是成本的主导因子，不是 W。** 跨库对照时至少要同时给出 C 和 W 两个数，只写 W 会误导。

### 6.3 MUTANT 的 window_length 敏感性

`returnA` 单样本耗时（CPU 测量）：

| W | 5 | 20 | 70 |
|---|---|---|---|
| `returnA` ms/样本 | 3.3303 | 3.3338 | 3.3444 |
| 其中 `np.corrcoef` | 0.0610 | 0.0632 | 0.0692 |

**W 变化 14 倍，`returnA` 纹丝不动。**

### 6.4 逐样本评分循环（P2）的影响

`as_shipped` 与 `core_only` 之差（即 `Model.py:177-180` 逐样本同步循环的代价）：

| 数据集 | b=1 | b=64 | b=120 |
|---|---|---|---|
| SMAP | 1.1% | 5.2% | 5.2% |
| MSL | 0.1% | 2.5% | 2.6% |
| SWaT | 0.2% | 2.6% | 2.5% |
| WADI | 0.1% | 1.1% | 1.0% |

**P2 不是瓶颈**（batch=1 时只有 1 个样本；batch=120 时也只占 1~5%）。向量化值得做，但不是关键路径。

**字段说明**

| 字段 | 含义 |
|---|---|
| `cost.n_params` / `weight_mem_MB` | 参数量 / 权重显存（`n_params` 为 batch=1 实测值，MUTANT 需按 §1 脚注折算） |
| `cost.flops_per_window` / `macs_per_window` | 单窗口前向 FLOPs / MACs |
| `cost.flops_per_timestep` | = FLOPs / window_length（每输入时刻算力，附列） |
| `cost.midstack_flops_share` | 中间块（`self.attmamba` 8 层）占全模型 FLOPs 比例（仅 SECOND） |
| `cost.counter_ops_seen` / `counter_ops_missing` | 计数器已计入 / 未计入的算子 |
| `latency.{as_shipped,core_only}.{batch}` | 延时；含 `mean/std/min/p50/p95/reps_ms/timed_iters` |
| `latency.*.ms_per_window` | = mean / batch |
| `midstack_latency.{batch}` | 中间块 8 层微基准（仅 SECOND） |
| `memory.{batch}` | `after_load_MB` / `inference_peak_MB` / `reserved_peak_MB` / `activation_delta_MB` |
| `protocol.*` | 测量口径与元数据（`harness_sha256` / 采样点 / 线程数 / cwd 等） |
| `ckpt.*` | 权重来源与 SHA256，`weights_loaded` 标明是否用了真实权重 |
