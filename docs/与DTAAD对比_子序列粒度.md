## 2. ⚠️ 读这张表前必须知道的三件事

### 2.1 「追回 oracle」不是 POT 的功劳，是标定本身在测试集上搜

**这是最容易被误读、也最容易被审稿人抓的一点。**

| 方法 | 候选阈值数 | 依据 |
|---|---|---|
| `bf_search`（oracle） | **700**（百分位 93→100，步长 0.01） | 测试集标签 |
| 本工作「标定」 | **84**（`level` 12 档 × `scale` 7 档） | 测试集标签 |

**两者都是「在测试集标签上搜最优阈值」，只是一个搜 700 个点、一个搜 84 个点。** 所以标定列几乎必然逼近 oracle——它本来就是一个粗网格的 oracle 搜索。

> **因此：POT 标定列不能声称是"标签无关的阈值选择"。** 真正标签无关的是**固定参数列**（全数据集统一 `(level, scale)`，不做任何搜索），其数值见 [阈值选择结果 v2](阈值选择结果_对齐DTAAD.md) §1 的 ① 列。

### 2.2 训练范围不同——这不是纯粹的方法对比

| | 本工作 | DTAAD |
|---|---|---|
| SMAP 训练数据 | **全 53 个子序列**（135183 行） | **仅 `P-1` 一个子序列**（8505 行左右） |
| MSL 训练数据 | **全 27 个子序列**（58317 行） | **仅 `C-1` 一个子序列**（2264 行左右） |

DTAAD 的 `load_dataset()` 同时加载 `P-1_train.npy` 与 `P-1_test.npy`，即**训练和测试都在同一条子序列上**。我们的模型在全数据集上训练，再在 `P-1` 上测试。

**数据量差约 16×（SMAP）/ 26×（MSL）。** 所以本工作的 F1 更高，**不能直接归因为"方法更强"**，训练范围是主要混杂因素。

### 2.3 WADI 的两边问题性质不同

| | 本工作（SECOND） | DTAAD |
|---|---|---|
| WADI F1 | 0.9459 | 0.5455 |
| 召回 R | **1.0000** | **0.3910** |
| 问题性质 | **指标退化**——测试集只有 1 个异常段（长 175），point-adjust 使命中 1 点即 R=1.0；F1 完全由 precision 决定 | **模型漏检**——漏掉 61% 的异常 |

**两者不是同一类问题，不能互相佐证。** WADI 在本工作中需单列讨论（PRD3.1 §5）。

| **batch size** | SMAP/MSL/SWaT 60 ｜ WADI 24 |

| **推理模式** | **未调用 `model.eval()`** → dropout（0.1）在推理时激活，分数与阈值**不可复现** |

| 数据集 | 拼接总长 L | 评测范围 `[0, L−⌊0.35L⌋)` | 覆盖 |

| SMAP | 427617 | **[0, 277952)** | 65% |
| MSL | 73729 | [0, 47924) | 65% |

- `MSL / C-1` 位于 `[0, 2264)` → **在评测范围内**，可离线切片
- `SMAP / P-1` 位于 `[354374, 362879)` → **超出评测范围**，需单独补一次前向（8435 窗口）

## 4. 为什么本工作的数字更高

**归因（按重要性排序）**：

1. **训练数据范围**：我们在全 53（SMAP）/ 27（MSL）个子序列上训练，DTAAD 只在被评测的那一条上训练。数据量差 16~26×。这是最大的混杂因素。
2. **上下文窗口**：W=70 vs W=10，可用的时序上下文差 7 倍。
3. **模型容量**：隐层 512 / 230M 参数 vs 隐层 16 / 1 层 transformer。DTAAD 的设计目标是**速度**——论文明确其卖点是 *"62%–99% less training time"*（Table 6），即**用容量换速度**。
4. **对齐的部分**：阈值规则、point-adjust、POT 实现均已逐行对齐，**这两列在方法上没有差异**。

> **结论**：这是一个**精度–效率取舍**，不是"同一预算下的方法优劣"。
> 本工作用远高于 DTAAD 的计算量换取更高的 F1；[PRD2 推理成本统计](PRD2_推理成本统计.md) 已量化该差距。
> **论文中必须把这条写进对比表的注脚**，否则高 F1 会被误读为纯方法优势。

## 5. 保留的问题

1. **val ⊂ test**（`main.py:168-175`）：`val_data = test_data[-n:]` 应从 `test_data0` 取。该 bug 使 ckpt 的最优 epoch 是在测试集子集上选出的，**所有已报数字都带乐观偏差**。且它砍掉了 35% 的测试集，导致 SMAP 有 18/53 个子序列（含 `P-1`）根本没被评测。
2. **推理未调 `model.eval()`**：dropout 激活，分数与阈值不可复现。
3. **WADI 的 ckpt 是 W=140**，与其余三格不一致。
