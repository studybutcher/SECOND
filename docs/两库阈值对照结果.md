## 2. 关键发现

### F1. ⚠️ 固定参数列 `(0.98, 1.0)` **不可靠**——它在 SECOND 上好看是运气

**MUTANT 在 SWaT 上用固定参数只有 `0.1432`**，标定后是 `0.9381`（差 0.79）。而 SECOND 在同一格上是 0.9536。

原因：该规则取的是**训练分数的 0.98 分位**，而 MUTANT 的 SWaT 上训练/测试分数分布错位——它的好阈值落在测试分布的 **99.78 分位**附近。

> **推论**：`(0.98, 1.0)` 不是通用配置，**不能作为"label-free 的公平下界"跨库使用**。
> PRD3.1 §3.2 原推荐"固定参数作主表"需要修正——**主表应用标定列**（两库同 procedure），
> 固定参数列降为附注，并说明它只在部分 (库, 数据集) 组合上可用。

### F2. 标定后的实际对比

| 数据集 | SECOND | MUTANT | 差 | 判断 |
|---|---|---|---|---|
| SMAP | 0.9678 | **0.9725** | −0.0047 | ⚠️ **落在 seed 方差内，下不了结论**（见 §3） |
| MSL | 0.9389 | 0.9396 | −0.0007 | **平手** |
| SWaT | **0.9837** | 0.9381 | **+0.0456** | ✅ **SECOND 决定性领先** |
| WADI | 0.9511 | **0.9859** | −0.0348 | ⚠️ **失效模式不同，不可直接比**（见 F4） |

**SECOND 的明确优势在 SWaT**：不仅 F1 高 0.046，而且形态不同——MUTANT 是**高精度低召回**（P=0.9879 / R=0.8940，漏掉 10.6% 的异常），SECOND 两者都高（P=0.9752 / R=0.9922）。

### F3. MSL 上两库天花板相同，且都到不了 0.95

| 库 | oracle | `F1≥0.95` 带宽 |
|---|---|---|
| SECOND | 0.9408 | **无** |
| MUTANT | 0.9410 | **无** |

两个模型的 MSL 上限都卡在 **0.941** 附近，且**都不存在 F1≥0.95 的可用阈值带**。这是**数据集 + 指标的性质**，不是某个模型的问题——论文里应写明，否则会被误读为"调参没调好"。

### F4. ⚠️ WADI 两库的退化程度差 54 倍

| 库 | 标定 F1 | `F1≥0.95` 带宽 | 失效模式 |
|---|---|---|---|
| SECOND | 0.9511 | **0.1%**（`level` 窗口宽 0.0000） | **指标退化**——R≡1.0，F1 完全由 precision 决定 |
| MUTANT | 0.9859 | **5.4%** | 相对正常，异常点分数铺得更开 |

**这推翻了"WADI 的刀锋是数据集通病"的猜测**——同一个数据集、同一个 point-adjust 规则，MUTANT 的可用带是 SECOND 的 54 倍。

**SECOND 在 WADI 上的退化是它自己的分数分布造成的**：其 `abs(sum(x_a − mu))` 使异常点分数全部压在 171.57 以下，只有 **1 个点**能爬到阈值之上。

> 论文中 WADI 需单列讨论，且**不能把原因推给数据集**。

### F5. 标定对两库都有实质收益

| 数据集 | SECOND 标定收益 | MUTANT 标定收益 |
|---|---|---|
| SMAP | +0.0212 | +0.0223 |
| MSL | +0.0048 | +0.0075 |
| SWaT | +0.0301 | **+0.7949** |

## 3. ⚠️ 未解决：SECOND 的 seed 方差

**SECOND 的推理依赖随机种子**（dropout 开启，见 [阈值选择结果 v2](阈值选择结果_对齐DTAAD.md) §7a）：

- 固定 seed 时**逐位可复现**（实测 seed=42 两次运行 `max|Δ| = 0`）
- 但**换 seed 结果会变**——历史日志中 SMAP oracle 在 **0.9703 ~ 0.9751** 之间漂移
- 本次缓存拿到 **0.9684**（偏低的一次）；MUTANT 是 **0.9723**，**正好落在这个区间中间**

**所以 SMAP 的 −0.0047 落在噪声内，目前无法判断谁更好。**

**待办**：SECOND 侧跑多 seed（如 42~46），报 **mean ± std**，与 MUTANT 的确定值并排。

```
python bench/cache_scores.py --dataset <ds> --seed <seed>     # 每 seed 一次前向
python bench/compare_two_libs.py                              # 汇总（加 mean±std 列）
```

## 4. 注意事项

1. **同 procedure 是可比的**（PRD3.1 §3.1.1）——两库 `pot_eval` 逐字节相同、同一 `q`、同一 `init_score` 口径、同一标定网格与准则。
2. **② 标定列是在测试集上选出来的**（84 点网格），**不是 label-free**。`bf_search` 是 700 点网格。两者都是 oracle 类，只是一个粗一个细。
3. **两库的分数尺度完全不同**（如 MSL：SECOND [66, 105] vs MUTANT [0.05, 44]），**并排表只比 F1，不比阈值绝对值**。
4. **两库都带 `val ⊂ test` 的乐观偏差**（同一个 `main.py:168-175` 的 bug）。
5. MUTANT 的 WADI 用 `out_dim=3`（其 `DATASET_CONFIG` 的设定），与 SECOND 的 `out_dim=5` 不同——**同为"WADI"，两库的模型配置不同**。
