# PRD6.2 · LSTM-AE 的 POT 初值标定 + PESR 的 POT 重训（MSL）

> 日期：2026-10-19 ｜ **状态：Stage 0 完成——LSTM-AE 18/18（§3.6）、PESR 18/18（§4.4）；PESR 重训待用户决定（现有数据不支持重训）**
> 上游：`PRD6.1_双模型双阈值_MSL.md`（36 runs 已完成）
> 原则：**不改算法内部结构；除下述两件事外，其余设置与 PRD6.1 完全相同。**

**一句话口径**：
- **LSTM-AE**：不重训，沿用现有 ckpt，只给它的 POT 选一张 `scale` 表，让 POT 不全为 0。
- **PESR**：只重训 POT 一侧，用验证集 POT F1 选 ckpt；bf 列沿用现有存档。
- 模型、POT 实现（`pot_eval`/`spot.py`）、point-adjust、噪声、数据划分、seeds、η、
  dropout（保持开启）全部不动。

## 0. 背景（只保留影响本轮口径的两条）

### 0.1 LSTM-AE 的 POT 全 0 是阈值膨胀

PRD6.1 §5.3 实测：静态 `pot_dtaad` 的有效阈值是
`quantile(init_score, level) × scale`，`init_score` 取**全训练集**。
训练集加噪后，这个分位数从 152 涨到 2151（×14），测试分数几乎不变，
于是 TP=FP=0。**不需要动模型，只需要把 LSTM-AE 的 `scale` 标定到它的分数尺度上。**

### 0.2 现有 `best.pt` 恒为 epoch 0（只影响 PESR 重训的实现）

`main.py:378-385` 在 val 前 `load_state_dict(save_path)`，`flag` 从 epoch 0 后恒为 1：

- epoch ≥ 1 的 val 评的是 reload 回来的 epoch-0 权重，save 的也是它；
- epoch ≥ 2 从 e0 重新走一个 epoch 后被丢弃；
- 因此现有所有结果都是 **epoch-0 模型**。

**本轮的处理**：
- **LSTM-AE**：不重训，接受现有 epoch-0 ckpt，只标定 `scale`。
- **PESR**：要选 POT 原生 ckpt，就必须让训练真正顺序走完 10 epoch；
  为此新增一条**独立**的 POT 重训路径，**不修改**现有默认训练路径与历史行为。

## 2. 协议总览

|---|---|---|---|

> 但它只用于 POT 列的阈值标定，bf 列用的是存档数字，不存在“同一 ckpt 两个阈值
> 互相挑最优”的问题。

### 2.1 与 `docs/阈值选择结果_对齐DTAAD.md` 的 ①/③ 的关系

> **本轮 POT 列明确采用 ③（标定最优），不是 ①（固定参数）。**
> ③ 的完整定义见下方 §2.1.1；`scale=1.0` 的 ① 只作为对照列保留。

| 口径 | 定义 | 本项目对应 |
|---|---|---|
| **① 固定参数** | `(level, scale) = (0.98, 1.0)`，全数据集统一，无调参 | **PRD6.1 的 POT 列就是 ①**（`q=1e-3`，`init_score`=全训练集） |
| **② oracle** | `bf_search` 在测试标签上搜 | bf 列 |
| **③ 标定最优** | 逐数据集（本轮逐 η）选 `(level, scale)`；原文档的 ③ 在**测试集**上选 | **PRD6.2 的 POT 列是 ③ 的验证集版本** |

#### 2.1.1 本轮 ③ 的精确定义（可复现）

```
固定：q = 1e-3, level = 0.98, init_score = 全训练集窗口分数
可变：scale ∈ S（见 §3.3）
选择（主口径 per-run）：
      s*(η,seed) = argmax_{s∈S}  val_point_adjust_F1(η, seed, s)
      （对照 per-η shared：argmax_s mean_seed val_F1，见 §3.3）
评测：th = base_th(η,seed) × s*(η,seed)
      （base_th = pot_eval 在 scale=1.0 下的阈值）
      只用 test_score 与 test_label 算 F1，阈值计算不碰测试标签
```

> 选择粒度由“每个 η 一套、3 seeds 共用”改为 **per-run**：3 个 seed 的
> 分数尺度不同（最优绝对阈值可差 ~20%），共享 `scale` 会系统性偏低。
> 两种粒度的数字都记录在 §3.6，主表用 per-run。

- **只有一个自由度**：`level` 固定，`scale` 与绝对阈值 `th` 一一对应；
  `(level, scale)` 只是参数化，报告以 `th` 为准（F5）。
- **③ 不是 ①**：① 是 `s≡1.0`、完全不调参；③ 用验证集标签选 `s`。
  两者必须分列报告，不能拿 ③ 的数字冒充 ①。
- **与原文档 ③ 的两点差异**：(a) 原 ③ 在测试集上选，本轮在**验证集**上选；
  (b) 原 ③ 同时扫 `level` 与 `scale`，本轮固定 `level=0.98`，只扫 `scale`。
  两点都让本轮 ③ 比原 ③ 更保守。
- **`val ⊂ test` 的实质影响**：val 是截断 test 尾部的 35%，占测试窗口的
  ≈54%。用 val 选 `s` 等于用一半测试点的标签做标定。因此 §3.6 同时报告
  **完整 test**（与 PRD6.1 可比，但对 ③ 偏乐观）与 **held-out test**
  （去掉与 val 重叠的窗口，更诚实）。两者都报，不混用。

关键区别：

1. **PRD6.2 不是为了复现 ①，而是因为 ① 对 LSTM-AE 失效。**
   `scale=1.0`（加上 `level=0.98`）正是把阈值推到 2151、导致全 0 的原因；
   要“不全为 0”，`scale` 必须离开 1.0。这一步在定义上就是 ③，不是 ①。
2. **标定集不同**：原文档的 ③ 在测试集上选；PRD6.2 在验证集
   （`test_data[-35%]`）上选，不碰测试标签。论文表述应为
   **“validation-calibrated, test-label-free”**，不能写成“无调参的 ①”。
3. **只有一个自由度**：`docs/阈值选择结果_对齐DTAAD.md` F5 已证明
   `(level, scale)` 的等价组合对应同一个绝对阈值。本方案固定 `level=0.98`、
   只调 `scale`，等价于为每个 η 选一个绝对阈值；**报告时以 `th` 为准**，
   `(level, scale)` 只是参数化。
4. **主表建议同时保留 ① 列与 ③ 列**：① 列如实显示 LSTM-AE 全 0，
   ③ 列显示标定后恢复到多少；不要用 ③ 的数字冒充 ①。

### 2.2 `(0.98, 1.0)` 到底从哪来

1. **不是 DTAAD 给 MSL 的值。** DTAAD 的 `lm_d` 里 MSL 是 `(0.999, 1.04)`；
   该组合在本模型上实测 F1=0（`PRD3.1` 方案 B、`阈值选择结果_对齐DTAAD` §2）。
   DTAAD 的表是**按它自己模型的逐子序列手工调出来的**（`params.json` 中
   SMAP `P-1_`=(0.98,1)、`A-4_`=(0.991,1.06)；MSL `C-1_`=(0.999,1.04)、
   `C-2_`=(0.9999,1.5)），跨模型不迁移。
2. **`(0.98, 1.0)` 是 PRD3 设的“全数据集统一对照参数”**：
   `q=1e-3, level=0.98, scale=1`，用来回答“不做 per-dataset 调参时 POT 是什么水平”。
   它在数值上恰好等于 DTAAD 的 **SMAP** 条目，但用法是“统一默认”，
   不是“从 DTAAD 抄 MSL”。
3. **`level=0.98` 不是手填的阈值**：SPOT 的 `initialize()` 取
   `init_score`（全训练集分数）的 98 分位作为 `init_threshold`，`scale=1.0`
   表示不再缩放。静态模式下 `th = quantile(init_score, 0.98) × scale`。
4. **① 是 a priori、无调参**；文档明确它“不能写成我们的 POT 配置”。
   **③ 才是标定列**：原文档的 ③ 在测试集上选，本 PRD 在验证集上选。
   两者都不是 ①。

### 2.3 DTAAD 的 `lm_d` 是不是用测试集标定的？

**仓库内的证据指向“是”，或至少是在被评测的数据上手工调出来的**：

1. DTAAD 的 `main.py` 只有 train/test，**没有 validation split**；
   `load_dataset` 返回的 train 无标签，唯一能用于调阈值的标签就是 **test 标签**。
2. `lm_d` 是硬编码表：`constants.py` 里 MSL 取 `(0.999, 1.04)`；
   `params.json` 里逐子序列不同（`C-1_`=(0.999,1.04)、`C-2_`=(0.9999,1.5)、
   `T-4_`=(0.9999,1.5)），是逐项调参的典型特征。
3. 仓库没有提供标定脚本或标定集说明，无法从代码“证明”；
   但若它做过任何有监督标定，可用的标签只有测试集。

**对本工作的含义**：

- **① 比 DTAAD 更严格**：完全不调参；
- **③（本 PRD 的 val 标定）与 DTAAD 的 `lm_d` 同性质，但更保守**：
  我们用验证集，若 DTAAD 是在测试集上选的，则我们用的标签更少；
- 论文里**不能写“DTAAD 的 `lm_d` 是 label-free”**；应写成
  “DTAAD 使用逐子序列手工标定的常量，我们报告无调参的 ① 与验证集标定的 ③”。

## 3. LSTM-AE：只标定 POT 初值（不重训）

### 3.1 输入

现成的 18 个 ckpt：

```
checkpoint/lstmae_robust_gauss/lstmae_MSL_gauss_noise<η>_seed<s>/best.pt
η ∈ {0, 0.05, 0.10, 0.15, 0.2, 0.5}，s ∈ {42, 7, 17}
```

### 3.2 计算

对每个 `(η, seed)`，加载现有 ckpt，**只做前向**：

1. `init_score`：全训练集分数（与 `compute_init_score` 完全一致）。
2. `val_score`：验证集分数（`test_data[-35%]`，与现有 ckpt 选择同一段）。
   ⚠️ 用 **`shuffle=False`** 的 loader：`main.py` 的 `val_loader` 是
   `shuffle=True`，随后直接拿打乱后的 `val_score` 对 `val_label` 算 F1
   （既存错位；因 `best.pt` 恒为 epoch 0，该错位不影响历史 ckpt，
   但标定必须用对齐的分数/标签）。
3. `base_th`：`pot_eval(init_score, test_score, level=0.98, scale=1.0)` 的
   `pot_dtaad` 阈值（与 PRD6.1 完全相同的路径）。
4. 对 scale 网格逐个算 val / test / held-out test 的 point-adjust F1：
   `th(s) = base_th × s`。

没有训练、没有改模型、没有改 POT 实现。

### 3.3 scale 表（“选一个表”）

固定 `level=0.98`、`q=1e-3`（与 PRD6.1 的 fixed paramset 相同），只选 `scale`：

```
scale ∈ geomspace(0.03, 1.20, 81)  ∪  {0.01, 0.02, 1.0, 1.5, 2.0}
        （81 个对数均匀点，相邻比值 ≈1.043）
```

> `1.0` 必须显式加入网格：它对应 ①（固定参数）的对照列；`geomspace`
> 的格点并不恰好落在 1.0 上。

**选择规则（主口径：per-run）**：

```
对每个 (η, seed) 独立地：
    s*(η, seed) = argmax_{s∈S}  val_POT_F1(η, seed, s)
```

- 平分时取较大的 `scale`。
- 每个 `(η, seed)` 是一个独立训练出来的模型，部署时也应当各自在自己的
  val 上标定；因此 per-run 是默认口径。
- 若某个 run 的所有 `s` 的 val F1 仍为 0，则该 run 记为“不可恢复”，
  **不重训、不硬救**，在表里如实标注。

**对照口径（secondary：per-η shared）**：

```
s*(η) = argmax_s  mean_{seed∈{42,7,17}}  val_POT_F1(η, seed, s)
```

- 保留这一列是为了和 §2.1.1 最初声明的“每个 η 一套表”对照。
- **实测发现 3 个 seed 的分数尺度不同**（同一 η 下最优绝对阈值
  `th*` 可差 ~20%），共享 `scale`（比值）并不等于共享阈值，所以
  shared 口径会系统性偏低；结果表两列都报，但主表用 per-run。
- 附表给逐 seed 各自的 `argmax_s`、与次优的 val 差，看标定是否稳定。
- **为什么必须用对数网格**：`base_th` 随 η 从 ≈149 涨到 ≈2168，而“有用”的
  绝对阈值大致固定在 O(10²)，所以 `s*` 横跨 ≈0.065–0.91。最初用的线性
  粗网格（0.001–1.0）在低 `s` 端太粗：η=0.10 的 s* 落在 0.1 与 0.2 之间，
  粗网格只能选到 0.10，val F1=0.28；换成对数网格后同一 run 的
  s*=0.1507，val F1=0.77。**粗网格会把“标定”误判为“不可恢复”。**

### 3.4 测试

用 `s*(η)` 在测试集上算一次：

```
th = base_th(η, seed) × s*(η, seed)   # base_th = pot_eval(..., scale=1) 的阈值
F1 = point-adjust(test_score, test_label, th)
```

每个 seed 一个结果，报 mean±sd。同时报：
- **完整 test**：与 PRD6.1 相同的 47,854 个测试窗口（对 ③ 偏乐观）；
- **held-out test**：去掉与 val 重叠的窗口后剩下的 22,049 个窗口
  （`val_start_row - W`，见脚本注释）；
- **bf held-out**：在**同一 held-out 子集**上用 `bf_search` 选阈值的
  oracle 上界，用来把“去掉测试标签的代价”与“子集本身变难”分开；
- **① 对照**：`s=1.0` 在同两列上的 F1（LSTM-AE 预期为 0）。

### 3.5 产出

- `results/threshold_lstmae_potcal/`：逐 run JSON（`s*`、`init_threshold`、`th`、P/R/F1、
  val F1 曲线、held-out 与 bf oracle）。
- `results/threshold_lstmae_potcal/scale_table.md`：per-run 与 per-η shared 的表。
- 成本：18 个 ckpt 只做前向 + bf 对照，实测 **≈10 min**（单卡，与其他任务共享）。

主口径 **per-run ③**（每个 `(η,seed)` 用自己的 val 选 `s*`），
`th* = base_th × s*`；所有数字为 3 seeds 的 mean±sd：

|---|---|---|---|
| 0 | 0.8298 | 0.6000 ± 0.0651 | 0.4352 ± 0.0246 |
| 0.05 | 0.2179 | 0.5465 ± 0.0663 | 0.4293 ± 0.0176 |
| 0.10 | 0.1507 | 0.5657 ± 0.0505 | 0.4432 ± 0.0089 |
| 0.15 | 0.1196 | 0.5768 ± 0.0571 | 0.4581 ± 0.0209 |
| 0.20 | 0.1042 | 0.5676 ± 0.0852 | 0.4584 ± 0.0363 |
| 0.50 | 0.0572 | 0.5518 ± 0.0402 | 0.4263 ± 0.0454 |

**读数**：

1. **POT 不再全 0。** 完整 test 从 ① 的 0.05 / 0 / 0 / 0 / 0 / 0 恢复到
   **0.652 → 0.578**，held-out 从 0 恢复到 **0.481 → 0.435**。
   这是纯阈值标定的结果，模型、ckpt、POT 实现都没有动。
2. **选出来的绝对阈值几乎不随 η 变。** `th*` 稳定在 **129–136**
   （逐 seed 119–155），而 `base_th` 从 **153** 涨到 **2151**
   （逐 seed 148.4–2168.2，η=0→0.5）；`s*` 从 0.87
   降到 0.06 只是在抵消训练分数分位数的膨胀。这说明 ① 的失效是纯粹的
   尺度问题，不是模型分数坏了。
3. **per-run 明显优于 shared。** 同一 η 下 3 个 seed 的最优绝对阈值不同
   （例如 η=0：124.2 / 129.0 / 146.4），共享 `scale`（比值）会把其中
   两个 seed 推到坏阈值上：test 低 **0.05–0.09**，held-out 低
   **0.04–0.05**。因此主表用 per-run；shared 只作为“更保守的旧口径”对照。
4. **完整 test 比 held-out 高 ≈0.14–0.17**，这是 `val⊂test` 的乐观量。
   论文/结论应以 held-out 为准；与 PRD6.1 的完整 test 对照时，要标明
   ③ 的完整 test 用了 val 标签。
5. **与 bf 的差距**：held-out 上 ③ vs bf oracle 为
   0.481/0.557（η=0）、0.497/0.555（0.05）、0.490/0.548（0.10）、
   0.486/0.495（0.15）、0.486/0.538（0.20）、0.435/0.490（0.50）。
   即 **去掉测试标签的代价约 0.01–0.08 F1**，η=0.15 最小、η=0 最大。
   完整 test 上 ③ 0.652 vs 存档 bf 0.677（η=0），差 0.025。
6. **选择是尖峰不是平台。** 平台中心（max−0.005 内取中位 scale）在 18/18
   个 run 上都等于 argmax；argmax 与次优的 val 差为 0.006–0.124，
   说明 LSTM-AE 的 val 曲线在最优附近足够陡，argmax 不是在噪声上追涨。

## 4. PESR：只重训 POT 一侧

### 4.1 是否需要重训：先看不重训的结果

PESR 的 bf 列沿用存档（epoch-0 ckpt）。POT 列若要“用 POT 选 ckpt”，
就必须有 epoch ≥ 1 的 ckpt；现有循环里 `best.pt` 恒为 e0，没有可选的第二个点。

**但重训不是默认动作。** 先按 §4.4 用现有 ckpt 做 ③ 标定（与 LSTM-AE
同一套流程），得到“不重训的 PESR POT”数字；只有当它与 bf / ① 的差距
仍然明显、且差异可以归因于“epoch-0 ckpt 不是 POT 最优”时，才进入
§4.2 的重训。**是否重训由用户看过 §4.4 后决定。**

### 4.2 独立重训路径（不改默认路径）

新增 `main.py --ckpt-rule pot`（默认仍是 `bf`，历史行为逐字节不变）：

```
for epoch in range(10):
    train_one_epoch(model)              # 顺序训练，不 reload
    save(f'epoch{epoch}.pt')
    val_score  = is_anomaly(val_loader)
    init_score = compute_init_score(model, train_data)
    init_thr   = pot_eval(init_score, val_score, level=0.98, scale=1.0)['threshold']
    for s in scale_grid:
        val_f1[e, s] = adjust_predicts(val_score, val_label, abs_threshold=init_thr*s)
# 训练结束后：
(e*, s*) = argmax  mean_seeds val_f1[e, s]
test: th = init_thr_{e*} × s*
```

- 训练超参、噪声、seeds、η 与 PRD6.1 完全相同（W=70, bs=60, latent=256, lr=0.01,
  10 epoch, `optimizer.step()` 每 256 步, val=0.35）。
- 打分保持 PRD6.1 的行为：**不调用 `model.eval()`**，dropout 照旧。
- 每个 epoch 的 `init_thr` 与 `val_score` 落盘，便于复算。
- 选择粒度：每个 η 一套 `(e*, s*)`，3 seeds 共用；附表给逐 seed 选择。
- 额外评 `bf(e*)`（同一 POT ckpt 上的 oracle F1），用于分解“换 ckpt 的代价”。

### 4.3 产出

- `results/threshold_pesr_potnative/`：逐 run JSON。
- `scale_table.md`：η → `(e*, s*, th)`。
- 成本：18 runs × 10 epoch × 383 s ≈ 19.2 GPU·h；逐 epoch 打分 ≈ 8.6 GPU·h；
  **合计 ≈ 28 GPU·h，8 卡约 3.5 h**。开跑前 `nvidia-smi` 选空闲卡。

### 4.5 确定性校验：η=0 重复 4 次

为确认 η=0 的三个 seed F1 不是 dropout 抽样的偶然结果，用**完全相同的
命令**（同一 ckpt、同一 seed、同一数据流程）重复 4 次；每次独立进程、
独立输出目录（`results/threshold_pesr_repeat/rep{1..4}/`），并与原始
`results/threshold_pesr_potcal/` 对比。

| seed | 5 次 JSON 的 md5 | ③ test（val-argmax） | ③ held-out | ① test（s=1.0） | ① held-out |
|---|---|---|---|---|---|
| 42 | 全部相同 | 0.9290 | 0.8980 | 0.9290 | 0.8980 |
| 7 | 全部相同 | 0.9369 | 0.9232 | 0.9369 | 0.9232 |
| 17 | 全部相同 | 0.9065（s\*=1.045） | 0.8982 | 0.9253 | 0.8964 |

四次重复（含原始共 5 次）的 JSON **md5 完全相同**：`base_th`、
`bf_test`、所有 scale 行的 F1 逐位一致。

结论：

1. PESR 虽未调用 `model.eval()`，但脚本开头的 `set_seed(seed)`
   （含 `torch.cuda.manual_seed_all`）加固定的前向顺序，使 dropout mask
   完全可复现；**同一打分路径下 F1 是确定的**。
2. PRD6.1 §5.4 的 |Δ|≤0.0268 来自**不同打分路径**的对比：存档 bf 产生于
   训练进程（训练已消耗 RNG），复评 bf 是新进程加载 ckpt 后重新前向，
   两者 dropout mask 不同。它不是同一条命令的 run-to-run 抖动。
3. 因此同一 run 内 ③ 与 ① 使用**同一次前向的分数**，差异只来自阈值
   选择，不含 dropout 噪声。

> “Holm p<0.05 但 Bonferroni CI 含 0”（bf, η=0）；不要跨列配对。
> 若正文主比较只报跨 η 平均（单次检验），用单项 CI + raw p 即可。

η=0.5 的 bf 比较不显著是 LSTM-AE 的 seed7 崩到 0.2960（§5.1 读数 4）
把配对差分的方差拉大，不是 PESR 变差。

**要把这个检验写进论文，还需要补齐的事**：

1. **预先固定主比较**：建议只报 `bf×bf` 与 `POT①×POT③` 两族，
   在文档里写明 α=0.05、Holm 的校正族；不要事后从 5 列里挑最大的差。
2. **把配对依据写进方法**：即上面的 `set_seed → add_noise` 顺序；
   再报 Welch p 作敏感性分析（已列在产物表里）。
3. **n=3 的硬限制**：p 值依赖配对差的正态假设，而 n=3 无法检验它。
   非参数检验在 n=3 时最小双侧 p=0.25，**不可能显著**。若审稿要求
   非参数或稳健 p，需要把 seed 加到 **≥6**（Wilcoxon/符号检验在
   n=6 才能到 0.031）——这意味着 LSTM-AE 与 PESR 都要重训，
   成本见 §3.4 / §4.4。
4. **不要用边际 CI 重叠代替检验**：PESR 明显更高，边际 CI 已分离，
   但正式表述仍应是 paired Δ 的 CI。
5. **窗口级检验（可选）**：若要声称“在 47,854 个窗口上显著”，
   需保存逐窗口分数并按时间块做 block bootstrap（point-adjust 使
   窗口不独立）；当前 18 个 run 都没落盘逐窗口分数，需要改脚本重跑前向。
6. **口径一致**：本检验用完整 test（对 POT 偏乐观，val⊂test）。
   若正文改用 held-out 22,049 窗口，需用同一批 JSON 的 `free_f1` 重算，
   不能混用两列。

### 5.1.3 p 值与差分 CI 的关系（报告规范）

p 值和 Δ 的 95% CI 不是两套证据，而是**同一个 t 统计量的两种写法**：

```
t = Δ̂ / (s_d/√n),   df = n−1
p = 2·P(T_df ≥ |t|)
95% CI = Δ̂ ± t(0.975, df) · s_d/√n
```

双侧 α=0.05 下：

> **raw p < 0.05 ⟺ 0 不在“单项” 95% CI 内**

这是一步代数等价，不是两个独立结论。

**但多重校正会打破这个对偶**：

- `raw p` ↔ 单项 95% CI：严格对偶（n=3 时 t=4.303）。
- `Holm p` 是校正后的 p，**不能**直接配单项 CI。要配同时区间，需用
  Bonferroni/Šidák/step-down CI。本项目在
  `results/prd62_pesr_vs_lstmae_test.{md,csv}` 中给了
  **Bonferroni 同时 95% CI（m=6）**：df=2 时临界值 **t=10.886**
  （普通 95% 是 4.303），区间约宽 2.53 倍。
- Holm 是 step-down 程序，比 Bonferroni 保守度低，**两者不严格对偶**。
  例：`PESR bf − LSTM bf, η=0` 的 Holm p=0.0167<0.05，但
  Bonferroni 区间是 **[−0.0004, +0.5408]**，刚好含 0。这不是矛盾，
  是两种校正的保守度不同。

**建议的报告方式**：

1. **主比较只留两条**，各做一次检验，避免多重校正：
   - `PESR bf − LSTM bf` 的跨 η 平均（η=0–0.2）：
     Δ=**+0.2854** [95% CI +0.2484, +0.3224]，raw p=0.0009；
   - `PESR POT① − LSTM POT③` 的跨 η 平均（η=0–0.2）：
     Δ=**+0.2967** [95% CI +0.2797, +0.3137]，raw p=0.0002。
   单次检验下 p 与 CI 严格对偶，不需要再解释校正口径。
2. **逐 η 表降级为探索性/敏感性分析**：报 raw p + 单项 CI，表注写明
   “未做多重校正”或同时给 Holm p 与 Bonferroni 区间，不要混配。
3. **不要用两个模型各自的边际 CI 是否重叠来判断差异**：配对设计下
   应看 Δ 的 CI（§5.1.2 的对象）。

**对 p 值的解读边界**：

- `p ≥ 0.05` 只表示“没有足够证据拒绝无差异”，**不等于两模型相同**。
  要主张等价，需要 TOST + 预设 margin（如 |Δ|<0.01）；n=3 的 CI
  太宽，当前做不到。
- `p < 0.05` 只表示“有差异”，不表示“差异大”。本文的 Δ≈0.28–0.30、
  区间下界 0.25 以上，统计与实用上都显著；反过来，dz=105 这类数字
  是 n=3 + 配对差近乎常数造成的，不能单独当效应量卖点。
- `p` 不是 H0 为真的概率，0.05 也不是自然常数；n=3 时 p 完全依赖
  配对差的正态假设（非参数检验最小双侧 p=0.25，§5.1.2 第 3 条）。
  因此 **CI 作为主报告，p 作为辅助**。

**两阶段填表**：
1. 先用**现有 ckpt** 把两模型的 POT 列都填成 ③（§3.6 / §4.4）；
2. 若用户决定重训 PESR，则 PESR POT 列替换为 `POT 重训 + (e*,s*)`，
   LSTM-AE 列不变；bf 列始终是存档。

最终表必须能区分“同 ckpt 的 ③”与“POT 原生 ckpt 的 ③”，不能混为一谈。

## 8. 风险与限制

1. **LSTM-AE 的 ckpt 仍是 epoch 0**：这是按你的要求不重训的代价。若标定后
   POT 仍全 0，说明该 ckpt 的测试分数与训练分位数完全不可比，表里如实记
   “不可恢复”，不通过重训去救。
2. **scale 用验证集标签选**：与现有 ckpt 选择同一套 `val⊂test` 口径，
   不新增泄漏；论文表述写成 “validation-calibrated, test-label-free”。
3. **PESR 只有重训后才会与 bf 存档不是同一个模型**：不重训时
   `bf(e_pot) = bf(archive)`；若重训，分解表必须同时报两者。
4. **PESR 打分仍有 dropout，但同路径可复现**：固定 seed + 同一脚本时，
   4 次重复逐位一致（§4.5）；跨路径（训练进程内的打分 vs 本脚本重新
   前向）才会不同。③ 与 ① 同属本脚本的同一次前向，其差异不含 dropout
   噪声。seed 间仍用 mean±sd 报告。
5. **scale 网格**：实测最优点没有落在边界（LSTM `s*` 0.057–0.910，
   PESR 0.998–1.094，均在网格内部），不需要扩网格。若后续换数据集
   出现边界点，再按“只看 val”的原则扩展。
6. **PESR 的 ③ 不优于 ①**：这是实测结论，不是实现错误。最终表若坚持
   统一用 ③，需要把这个负增益写进表注，不能只报 ③ 的完整 test
   而隐去 held-out。
