# PRD5.2 · LSTM-AE 在现有 robust 加噪协议下的结果（2026-10-10）

> 依据 `docs/PRD5.2_LSTM-AE_噪声协议定量验证.md`。
> **用户 2026-10-10 的决定：评测协议也原样复用，只换模型** —— 所以本文的主表就是
> `main.py` 的 F1（bf_search oracle 阈值 + point-adjust），**另附一把好尺子**（未调整 AUROC/AUPRC）。
>
> **两条结论：**
> 1. **加噪对 LSTM-AE 的异常排序能力没有影响** —— AUROC 在 η 0→0.5 全程平在 **0.587–0.595**。
> 2. **F1 在同一批 18 个 run 上摆幅 0.458（2.6×），而 AUROC 只摆 0.030** ——
>    一次非常干净的"F1 不测量模型质量"的量化演示。

---

## 1. 设置（只换模型，其余照抄）

| 项 | 值 | 来源 |
|---|---|---|
| 模型 | **LSTM-AE**（`model/Model_lstmae.py`，类名 `patchattmamba` 以接上 `main.py`），**0.33 M 参数** | 本 PRD |
| 加噪 | `main.py --noise` → `add_noise`，整行替换 U(−2,2)/±5/random_walk，时机在 `preprocess` **之后** | `main.py:118-142,225` |
| 档位 | **η ∈ {0, 0.05, 0.10, 0.15, 0.2, 0.5}** | `script/robust/*.sh` |
| 划分/W/bs | 全部走 `main.py` 现状（含 **val ⊂ test** 的既存缺陷） | `main.py:255-286` |
| 调度 | 10 epoch、Adam lr 0.01、每 256 步 `step()`、seed 42/7/17 | `main.py:299,314,324` |
| 评测 | **`bf_search` oracle 百分位阈值 + `adjust_predicts`**（= 现有协议） | `eval_method.py:95-119` |
| seed | **3 个**（42, 7, 17）⇒ **18 runs** | 本 PRD |

**唯一的两处新增**（都不改评测协议）：
① `main.py` 加 `--score-dump`，把 test 分数与标签落盘 → 事后算未调整 AUROC/AUPRC；
② `--backbone lstmae` 注册（`main.py` 的 `BACKBONE_REGISTRY`）。

**成本实测**：11 s/epoch，单 run（10 epoch + 评测）**2.5 min**。18 runs ≈ 8 min（3 卡并行）。

## 2. 主结果

### 2.1 逐 run（18 行见 `results/lstmae_robust/summary.md`）

### 2.2 按 η 汇总（seed 均值 ± std）

| η | **F1（现有协议）** | AUPRC | **AUROC（好尺子）** | n |
|---|---|---|---|---|
| 0.00（clean） | 0.6765 ± 0.033 | 0.1596 | **0.5942 ± 0.0035** | 3 |
| 0.05 | 0.4238 ± **0.196** | 0.1575 | **0.5939 ± 0.0035** | 3 |
| 0.10 | 0.5135 ± **0.173** | 0.1615 | **0.5949 ± 0.0018** | 3 |
| 0.15 | 0.5472 ± **0.208** | 0.1622 | 0.5873 ± 0.0071 | 3 |
| 0.20 | 0.5337 ± **0.232** | 0.1706 | 0.5919 ± 0.0151 | 3 |
| 0.50 | 0.5345 ± **0.198** | 0.1603 | 0.5888 ± 0.0067 | 3 |

base rate（异常窗占比）= **0.1388**（AUPRC=0.1388 即随机；AUROC=0.5 即随机）。

### 2.3 两把尺子的摆幅（同一批 18 个 run）

| 尺子 | 范围 | 极差 | 倍数 |
|---|---|---|---|
| **F1（现有协议）** | 0.2827 – 0.7411 | **0.4584** | **2.62×** |
| **AUROC（未调整）** | 0.5754 – 0.6051 | **0.0297** | 1.05× |

- **F1 在 η 各档内的 seed std（0.17–0.23）本身就大于各档均值之间的差（0.42–0.68）** ⇒
  连"clean 比加噪好"这个 F1 上的观感都是噪声。
- 最干净的一例：`η=0.20 / seed42` 拿到 **F1=0.7411（全场最高）**，而 `η=0.10 / seed7`
  F1=0.3204（全场倒数）—— 两者的 **AUROC 是 0.6051 vs 0.5953**，差 0.01。

## 3. 两条结论

### 3.1 加噪对 LSTM-AE 没有可测影响（好尺子口径）

AUROC 从 η=0 的 0.5942 到 η=0.50 的 0.5888，**差 0.005，在 seed 离散度（±0.004–0.015）之内**。
**50% 的训练行被替换成 ±2/±5 的整行垃圾，异常排序能力没有下降。**

AUPRC 同样无趋势（0.157–0.171，全档略高于 base 0.1388）。

> 这是**第三次**得到"加噪不咬人"的结果，但前两次是用 point-adjust F1 测的（坏尺子、
> 结论不可用），**这次是第一次用有分辨力的尺子、在一个确实能工作的模型上确认**。

### 3.2 LSTM-AE 的分数**有信息**，SECOND 的没有

| 模型 | MSL，未调整 AUROC | 未调整 AUPRC（base 0.1388） |
|---|---|---|
| **LSTM-AE**（本实验） | **0.587–0.605**（全程 > 0.5） | 0.154–0.190 |
| SECOND（`PRD5_T0结果` §0） | **0.4975** | 0.1380 |

⇒ LSTM-AE 是一个**弱但真实**的检测器；SECOND 的**分数层等价于随机**。
这也解释了为什么两者的 F1 形状完全不同：SECOND 的分数接近常量 ⇒ point-adjust 下
recall 被推到 ~0.98 ⇒ F1 恒定在 0.94（**伪高**）；LSTM-AE 的分数有结构 ⇒
recall 只有 0.57、F1 随阈值与分数分布剧烈摆动（**伪低且不稳**）。
**两种都不可用，但失败方式不同。**

## 4. 判据（PRD5.2 §8）

| # | 判据 | 结果 |
|---|---|---|
| **D1** η↑ ⇒ $E_N$↑（本实验用 **AUROC↓** 作等价判据） | **✗** 无趋势 |
| **D2** 不同 η 间无稳定差异 | **✔ 命中**（AUROC 极差 0.030，与 seed 离散度同量级） |
| **D3** LSTM-AE 退化明显而 SECOND 平 | ✗（两者都不退化；但 SECOND 的"平"来自塌缩，LSTM-AE 的平是**真的**没影响） |
| **D5** F1 与好尺子结论不一致 | **✔ 强命中**（见 §2.3） |

> **可以写**：在 `script/robust` 这套协议（整行替换 ±2/±5，η ≤ 0.5）下，
> 一个传统 LSTM-AE 的异常排序能力不受影响（AUROC 0.587–0.595，无趋势）。
> **不能写**：训练污染无害；也不能用 F1 数字做任何比较。

## 5. 对论文的两个用途

1. **方法学附录**：§2.3 那张"同一批 run，F1 摆 2.6×、AUROC 摆 0.03"的表，是
   **弃用 point-adjust F1 的最强证据**，且不依赖 SECOND 的任何特殊性（模型、数据、训练都换了）。
   建议直接进 appendix 或 response letter。
2. **R2 的一个抓手**：LSTM-AE 是"传统重构方法"的实例，它在这套扰动下**排序能力稳定但很弱**
   （AUROC 0.59）。与 SECOND 的 0.4975 并列时，可以谈"重构式检测器的判别力本身有限"，
   而**不要**谈"谁更鲁棒"（本实验没测出差异）。

## 6. 边界与未做

- **只做了 MSL**。SMAP / SWaT / WADI 可复用同一脚本（`DATA=SMAP zsh script/repr/lstmae_robust.sh`），
  成本约 8 min/数据集。
- **噪声 ≠ 异常**：本实验测的是"用部分损坏的数据训练"，不是"真实异常污染"（`PRD4_噪声` §5 同一限定）。
- **±2/±5 是绝对常数**（数据在 [0,1]），未做 σ 缩放版本；若要分离"强度太大 vs 协议无效"，
  见 `PRD5.2` §1.1(a)。
- **val ⊂ test 的既存缺陷沿用未改**（用户决定复用评测协议）。它让绝对 F1 偏乐观，
  但因为所有 η 档同病，**不影响 §3.1 的"无趋势"结论**。
- **未做**：per-epoch 曲线（`main.py` 只记 val F1、不记 MSE，JSON 里没有逐 epoch 值）。
